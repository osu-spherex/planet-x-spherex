# Шинэ өгөгдөл ирвэл: статик кубуудыг шинэчлэх

SPHEREx үргэлжлүүлэн ажиглаж байгаа, IRSA өгөгдлөө шинэ хувилбараар дахин гаргадаг
(https://irsa.ipac.caltech.edu/Missions/spherex.html). Хоёр зүйл өөрчлөгдөж болно: **шинэ ажиглалт нэмэгдэнэ**, эсвэл
**хуучин ажиглалт шинэ боловсруулалтаар, өөр файлын нэртэй буцаж ирнэ**. Таван объектын статик өгөгдлийг (`data/cubes/`)
нэг командаар шинэчилнэ: `python -m data.refresh` (даалгавар A-12). Python-ыг үндсэн фолдерын `.venv`-ээр ажиллуул.

## Гурван алхам

**1. Шалга — юу ч өөрчлөхгүй.**

```bash
python -m data.refresh --dry-run
```

Объект бүрт IRSA-аас одоогийн жагсаалтыг асууж (нэг query, зургаан детектор; эрүүл үед 8–30 сек), кэштэй
(`data/cache_dr1`) харьцуулна. Детектор бүрт нэг мөр: `barnard D1: 60 images in the archive, 60 already in the cache,
0 to download, 0 to drop`. Татах, хасах файл байвал нэрээр нь жагсаана:

| Тэмдэглэгээ | Утга |
| --- | --- |
| `+ … new` | шинэ ажиглалт |
| `+ … reprocessed l2b-v20-… -> l2b-v27-…` | ижил ажиглалт, шинэ боловсруулалт — хуучин файлыг **орлоно** |
| `- … replaced` | орлогдож буй хуучин хувилбар |
| `- … left out by the even subsample of 150` | гүн талбар (R Dra): детектор бүрт ≤150 зураг, цаг хугацаагаар жигд түүвэр |
| `- … no longer in the archive` | IRSA жагсаалтаасаа хассан зураг |

Бүгд `0 to download, 0 to drop` бол шинэ юм алга — энд зогс.

**2. Шинэчил.**

```bash
python -m data.refresh
```

(нэг объект: `python -m data.refresh barnard`). Дутууг татаж, объектын зургаан детекторын `cube.json`, `cube.f32`,
`flags.u8`, дараа нь `catalog.json`, `measure.json`, `spectrum.json`, `motion.json`, `coverage.json`-ийг дахин үүсгээд юу өөрчлөгдсөнийг
хэвлэнэ: `wise0855 D6: 43 -> 45 frames, last image …, qr2 43 -> dr1 45, l2b-v20 -> l2b-v27, pixels changed`.
`N downloads failed, nothing rebuilt` гарвал **ижил командыг дахин ажиллуул** — IRSA завгүй үедээ хүсэлтийн аравны нэгийг
503-аар буцаадаг; бүрэн татагдаагүй объектыг дахин бүтээхгүй. `done, 0 problems` гартал давт.
Орлогдсон хуучин файлууд дискэнд үлдэнэ (хэдэн MB гэдгийг хэвлэнэ); `--prune` устгана.

**3. Шалгаад нийтэл.**

```bash
python -m pytest tests -q
```

```bash
git status --short data/cubes
```

- Тест frame-ийн тоо, хэмжсэн утгаар бэхлэгдсэн тул шинэ өгөгдөлд унаж болно. **Тестийг өөрөө бүү зас** — унасан тест,
  шинэ тоог хүнд (төлөвлөгчид) үзүүл; утга яагаад өөрчлөгдсөнийг тайлбарлаж чадсаны дараа л хүн тестийг шинэчилнэ.
- `data/cubes/<obj>/<D#>/quicklook.png`-г нээж нүдээр шалга: объект төвдөө, сүүлийн epoch харагдаж байна уу.
- WISE 0855-ын D6 өөрчлөгдсөн бол хяналтын кубыг дагуулж шинэчил: `python -m data.control_cube`, дараа нь
  `python -m data.measure_static wise0855_control`.
- Frame-ийн тоо өөрчлөгдсөн бол `[A→B]`, `[A→P]` Issue нээ: `frontend/search/results.json` ба frontend-ийн тоон тестүүд
  кубын тооноос хамаарна.
- Commit, PR. Сайт кубуудыг build хийхдээ хуулдаг (`deploy/copy-cubes.mjs`), тиймээс `main` руу нэг push хангалттай.

## IRSA ажиллахгүй бол, эсвэл зөвхөн код өөрчлөгдсөн бол

```bash
python -m data.refresh --offline
```

IRSA-аас юу ч асуухгүй; кэшид байгаагаар куб, `measure.json`, `spectrum.json`, `motion.json`-ийг дахин үүсгэнэ (`catalog.json`,
`coverage.json` хөндөгдөхгүй). `data/motion.py` эсвэл `data/photometry.py`-г зассаны дараа бүх хэмжилтийг нэг дор шинэчлэхэд
мөн үүнийг ашигла. IRSA хариу өгөхгүй үед энгийн горим хадгалсан хуучин жагсаалтыг шинэ гэж **ашиглахгүй**, зогсоод хэлнэ.
